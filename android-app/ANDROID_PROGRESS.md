## Этап 2 - локальная медиатека (2026-11-14)

### Закрыто ПОЛНОСТЬЮ
- [x] БД v2 + миграция `MIGRATION_1_2` (без стирания данных): у треков `media_store_id`, `source_id`, альбом / исполнитель альбома / жанр / год / номер трека и диска, размер, MIME, папка, даты, `search_key`, `is_available` + `missing_since`; у папок `last_scan_at`, `is_accessible`. Схема `app/schemas/.../2.json`.
- [x] Сканер MediaStore (`MediaStoreScanner`): `IS_MUSIC != 0`, все поля одним запросом. Файлы без длительности (битые) не попадают в список и считаются «нечитаемыми». Если провайдер не вернул курсор, это ошибка, а не «пустая медиатека». **Заменено 2026-11-15:** сканер удалён, медиатека строится только из выбранной папки.
- [x] Сканер SAF-папок (`FolderScanner`): обход дерева, теги через `MediaMetadataRetriever`; файлы с тем же размером и датой изменения не открываются повторно. Отозванный доступ или отключённая карта памяти → папка «недоступна», её треки помечаются, а не удаляются.
- [x] Сверка с БД (`TrackReconciler`, чистая логика, юнит-тесты): вставка / обновление / пометка пропавших. Пропавший файл, который вернулся, восстанавливается с тем же id. Дубликаты «SAF-папка ∩ MediaStore» схлопываются по (папка, имя, размер).
- [x] Оркестратор (`LibraryScanner`): одна очередь, запросы сливаются (`ScanPlan.merge`); `ContentObserver` на MediaStore с задержкой, только пока приложение на экране (lifecycle); скан при запуске; ручное «Обновить медиатеку»; прогресс «Найдено N».
- [x] Обложки: Coil 3 + свой fetcher; миниатюра под размер элемента сохраняется JPEG в дисковом кэше с ограничением; «нет обложки» тоже кэшируется. Ключ включает дату изменения и размер, поэтому новая обложка подхватывается.
- [x] UI: список «Все треки» (сортировка по названию без учёта регистра, ё=е), счётчик и общая длительность, обложки, индикатор сканирования; снекбары с итогом («Медиатека актуальна, изменений нет», добавлено / обновлено / нечитаемые / недоступные папки). Настройки: «Обновить медиатеку» с временем последнего обновления, счётчик треков у каждой папки, «недоступно: N».
- [x] Пустые состояния: «ещё не сканировалось» / «музыка не найдена» с кнопками «Выбрать папку» и «Обновить медиатеку».
- [x] Большие библиотеки: запись пачками (лимит аргументов SQLite), тест БД на 10 000 треков; 2010 треков на эмуляторе.

## Архитектура (решение этапа 0)
Нативный **Kotlin + Jetpack Compose**, а не Tauri Android. Причины: в ПК-версии звук играет через `<audio>` + Web Audio в WebView, который Android останавливает в фоне; для фонового воспроизведения, `MediaSession`, уведомления, аудиофокуса и гарнитуры нужен нативный сервис (Media3, этап 3). Логику ПК (форматы, LRC, дубликаты, перемещённые файлы) переносим по матрице, а не кодом.

Версии: AGP 9.5.1, Gradle 9.9.1, Kotlin 2.4.21, KSP 2.3.14, Compose BOM 2026.09.00, Room 2.8.5, Navigation 2.10.2, DataStore 1.3.0, Lifecycle 2.11.0. `minSdk 28` (Android 9), `targetSdk 36`, `compileSdk 37` (его требуют свежие AndroidX). Версия приложения берётся из `package.json` (сейчас 2.0.7, debug = `com.playly.player.dev`, `2.0.7-dev`).
